01 · Start with a purpose

What makes a useful cluster?

Imagine you run a shop and want to tailor offers to customers who shop in similar ways. Each dot is one customer, plotted by monthly visits and monthly spending. Each colour shows a group found by clustering. Before using those groups, check whether the dots in each group sit close together, whether there are clear gaps between groups, and whether the measurements answer your question.

Try it: compare the first two plots. Where would you hesitate to assign a customer to one group? Then open the third card to see what happens when the shop changes its question.

Choose a card to see how its grouping could inform the shop’s decision.

From a visual check to a measurable one

In Section 2, you’ll measure how close customers are to their own group and how far they are from other groups. That is internal evaluation. In Section 3, you’ll see how external evaluation compares the groups with independent reference labels when those are available. To decide which products to promote, you would also need purchase information.

02 · Measure from within

A score is evidence. Not a verdict.

In Section 1 you judged the groups by eye. Here you’ll use internal metrics to check whether the points assigned to each group are close together and well separated from other groups. The scores use the plotted measurements and cluster assignments alone.

Try grouping the same points into two, three, then four clusters
  1. Choose Compact clouds and K-means. The plot contains three visible clouds. Set the number of clusters to 2 and notice how two clouds share a colour.
  2. Set it to 3. Each cloud now has its own group. Silhouette rises from about 0.57 to 0.79, Davies–Bouldin falls from 0.67 to 0.27, and Calinski–Harabasz rises from about 82 to 506. All three changes support the grouping you see.
  3. Try 4. One cloud is split and silhouette drops to about 0.64. Click points near the split to see how close they are, on average, to their own group and the nearest competing group.

For these points, three groups fit the geometry better than two or four. Try Curved groups next and compare the shapes in the plot with the scores. These metrics tend to favour compact groups, so use the plot and the purpose of the grouping when interpreting them.

All distances here are Euclidean, on two synthetic features with comparable numerical scales. K-means uses 12 deterministic starts. Agglomerative uses the chosen linkage. DBSCAN counts the observation itself in MinPts.

Observation 1

s = (b − a) / max(a, b)

a: mean distance to other members of its own group.
b: smallest mean distance to another group.

The highlighted dot is selected. Its group is bright; the nearest competing group is outlined in yellow. Singleton silhouettes are defined as 0.

Silhouette · higher is generally better

Ranges from −1 to 1. Positive values indicate a point is closer on average to its own group; near zero suggests ambiguity; negative values suggest another group is closer. The displayed score averages the retained observations.

Davies–Bouldin · lower is generally better

For each cluster, compare its average distance from its centroid with centroid separation from other clusters. Average its worst such ratio. A low ratio supports compact, separated groups; it does not prove practical usefulness.

Calinski–Harabasz · higher is generally better

Compare between-cluster dispersion with within-cluster dispersion, adjusted for the numbers of groups and observations: [B/(k−1)] / [W/(n−k)]. There is no universal good-score threshold; compare like-for-like datasets and feature preparation.

DBSCAN noise is excluded from these internal metrics. Coverage is always shown. Two DBSCAN settings can retain different subsets, so their scores alone are not a fair ranking. A score is unavailable with fewer than two retained clusters or one cluster per retained observation.

03 · Compare with a reference

Do the groups agree with what we know?

Section 2 asked whether groups look compact and separated. Here the question is how closely the fitted groups match a reference grouping for the same points. For example, cluster flowers using petal measurements, then compare the groups with known species. In this lab, the reference labels record which cloud generated each synthetic point. The algorithm sees only the coordinates during fitting.

Follow the same points across the two plots
  1. In the mini view beneath the navigation, choose Compact clouds, K-means, and 3 clusters. Select Reveal reference labels. The left plot shows the reference groups and the right plot shows the fitted groups. Both show the same points.
  2. Read the table by row. Each row is a reference group and each column is a fitted group. Each of the three rows puts all 24 points in a different column, so the memberships match exactly. Both ARI and NMI are 1.00.
  3. Change to 2 clusters in the mini view. Two reference rows put their 24 points in the same column. K-means has merged two reference groups, and agreement falls to about 0.56 ARI and 0.73 NMI.
  4. Select Rename cluster numbers. The column labels change while the counts and scores stay the same. The scores compare which points belong together.

Use the scores to judge agreement with the particular reference you chose. Species labels help when your aim is to recover species. If your aim is to group flowers by petal size, species agreement answers a different question.

Renaming changes the cluster identifiers while preserving memberships and agreement scores.

Fitted groups

Adjusted Rand Index · ARI

Compares whether pairs of observations are grouped together in both partitions. 1 means identical partitions; values near 0 indicate chance-level agreement; negative values can occur. Cluster names do not matter.

Normalized Mutual Information · NMI

Measures shared information between partitions, from 0 to 1, using arithmetic-mean entropy normalization here. It is not adjusted for chance, so many small clusters can inflate agreement.

External scores include every observation; DBSCAN’s −1 noise label is treated as one category for this comparison, not as a discovered ordinary cluster. Reference labels may describe a different question from your intended segmentation.

04 · Change the conditions

Does the pattern survive?

Section 3 compared a fit with reference labels. Here, the original fit is the baseline. We fit the same method again after shifting some measurements or adding unusual points, then ask whether the original observations still tend to group together.

Try changing the measurements
  1. In the mini view beneath the navigation, choose Overlapping clouds, Agglomerative, Ward and 3 clusters.
  2. Here, set both sliders to 0 and run the trials. Mean ARI is 1.00 because the same data and settings give the same grouping.
  3. Raise measurement perturbation to ±10 and run again. Mean ARI drops to about 0.73. Open a lower-scoring trial and look for points near the boundaries that now group with different neighbours.

The drop shows that membership depends on how precisely the points were measured. Try adding outliers with perturbation back at zero to see how unusual new observations can affect the groups of existing points.

Uses the shared data and parameters from the mini view. Each trial applies a new seeded perturbation, adds the selected outliers, and refits. K-means uses one start with a different seed per trial, deliberately testing initialisation as well. Other methods have no random initialisation here.

Read agreement with its context

We calculate ARI between baseline and trial memberships on the original observations only. Added outliers affect fitting but are excluded from this pair comparison. Noise is a category: agreement of 1 when both fits mark everything noise is stable rejection, not successful clustering.
